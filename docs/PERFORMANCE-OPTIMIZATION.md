# 游戏性能优化（2026-10-28）

## 现场使用

右上角「画质」可选自动、流畅优先、均衡、清晰。默认自动：普通电脑从均衡开始，手机及已知低内存／少核心设备从流畅开始；连续慢帧先降低细节与额外渲染，再降低像素，健康运行约20秒才逐级恢复。即使站着不动也会适配负载。手动选择会保存在当前浏览器，刷新仍保留。

现场配置较低的电脑可选「流畅优先」：关闭动态阴影与平面倒影、降低画面像素、缩短小构件的精细显示距离。近处主体建筑、道路、树木、车辆仍保留。电脑速度、碰撞、建筑坐标、载具数量、活动阶段和手动蛛丝规则没有按画质改变。

## 实施内容

- 树木采用近景细枝叶、中景树冠、远景简化立体树冠；小栏杆、窗框、空调片和路缘按距离细化。所有原始树木位置与地图数据仍保留，完整导出恢复全部细节。
- 立面、道路小构件和植被建立空间索引；可见序列没变则不重写实例缓冲，只上传使用中的矩阵／颜色区间。
- 停放车辆不再每帧重算姿态；缓存骑手关节矩阵与颜色，换色、刹车、上／下车时更新。离场缓存使用WeakMap，销毁释放批次。
- 交通外观更新按15／24／30Hz控制，交通模拟与玩家输入、运动物理继续使用原步长。当前角色之外的隐藏载具不再重复更新世界矩阵。
- 阴影按质量档分配尺寸并降低更新频率；太阳和阴影相机一起更新。只有清晰档在湖面可见、距离合适时开启受限频率倒影，手机保留较低预算。
- 蜘蛛侠连续蒙皮在加载期间由Worker并行生成，完成后转移缓冲；额外Worker约41.8KB、gzip约14.7KB，无需额外下载5.4MB角色模型。失败时原算法回退，形状、骨骼和蛛丝端点不变。
- 切到后台时跳过场景更新／渲染，恢复不追赶积压时间；进入作品时校园暂停，返回销毁iframe。首次模型尚未准备好时不渲染半成品的全校俯瞰画面。

## 可复现的测量

Node基准使用真实校园数据、固定出生视角及固定轨迹；属于CPU／几何／计划缓冲上传测量，不是GPU或现场低配电脑实测。

| 项目 | 修改前 | 修改后 |
|---|---:|---:|
| 出生视角可见静态三角形 | 1,128,179 | 307,043 |
| 静态实例变化区间／帧 | 3.87MB | 0.29MB |
| 静止交通视图更新 | 0.967ms | 0.151ms |
| 行驶交通视图更新 | 0.698ms | 0.286ms |
| 交通实例标脏范围／更新 | 12.2MB | 37.5KB |
| 500次步行模型更新 | 53.0ms | 4.43ms |

原交通状态、实例矩阵和颜色的SHA256前后相同。角色Worker输出和原算法逐字节相同。原始GeoJSON未修改。

```sh
npm test

node scripts/benchmark-static-scene.mjs

```

对照旧代码时可让 `PERF_SOURCE` 指向修改前的源码副本；优化前版本是Git提交 `20715f9`。`scripts/bake-spider-geometry.mjs` 仅用于离线制作／测量，产物在 `artifacts/spider-prebake/`，不是生产运行依赖。

主工程回归592项通过，包含输入、触控、交通、地图、模型、角色和活动服务。预算测试覆盖后台／作品暂停、偶发加载停顿、连续低至2FPS的压力、手动选择与慢恢复；模型测试覆盖取还车、换色、切换LOD、完整导出、独立释放和蛛丝手腕位置。

部署副本255项测试全部通过，`build:vercel` 成功。正式构建在独立本地服务、1280×720视口、同一出生位置、测试进程结束后进行对照：

| 浏览器最近采样窗 | 修改前 | 均衡档 | 流畅档 | 清晰档 |
|---|---:|---:|---:|---:|
| FPS | 41.1–41.4 | 120 | 120 | 85.2 |
| 主线程每帧工作 | 24.0–24.1ms | 3.4–3.9ms | 3.3ms | 4.1ms |
| 渲染像素倍率 | 1.75 | 1.0 | 0.85 | 1.5 |

这是本机 Mac17,2（10逻辑核心）应用内浏览器的短时对照，车流继续运行；不同档位的像素和特效不同，不能将这些FPS当成现场低配设备保证。已实际检查画质切换、阴影恢复、Worker准备成功、移动、穿战衣和844×390横屏布局；测试页无控制台错误。没有进行物理低配电脑或手机批量测试。
