# 200 人活动：客户端连接与后台恢复优化

2026-10-30；基于 `5f66278`。本轮不改地图、速度、按键、蜘蛛丝锚点、作品记录与活动权限。

## 改动

- 首次 `/api/live/state` 成功后，SSE 的 `open` 不再重复请求完整状态。初始每观众 GET 从 2 次变为 1 次；正常 SSE 轮换直接使用服务器的新完整快照。
- 关闭故障 SSE，单独维护一条重连任务；第一次等待随机 500–1000 ms，连续失败指数退避至随机 15–30 秒。仅有效快照重置失败次数，旧流的迟到事件不会修改新状态。
- 初始及定期 RTT 校时仍保留；时钟校准请求与可见恢复合并成单次在途请求，额外随机延后 100–1000 ms。短时间切回页面不重复 GET。
- `offline` 取消重试、关闭流；网络恢复后即使页面处于隐藏状态仍重新接收活动快照。隐藏页面不会因此丢掉主持人的最新阶段。
- 图形循环现在通过真实 `visibilitychange` 标记计时边界。即使浏览器后台完全停止 RAF，返回第一帧也不再补执行 100 ms 的移动/物理时间；正常前台长帧仍如实计入统计，并沿用原有 100 ms 物理步长保护。

这些改动减少重复请求和同一时刻的重连峰值，不代表已经实现跨标签共享一条 SSE，也不代表多个 Vercel 实例共享进程内缓存。

## 验证

```sh
node --test tests/live-client-lifecycle.test.mjs tests/live-client-reconnect.test.mjs tests/live-client-clock.test.mjs tests/visibility-frame-clock.test.mjs tests/render-cadence.test.mjs
node scripts/verify-live-client-browser.mjs
```

- 22 项定向测试通过。包含 200 个虚拟客户端首次请求计数、重连/恢复错峰、持续失败退避、迟到事件、取消清理、时钟保留和后台没有 RAF 的运动恢复。
- 200 虚拟客户端首次 GET 共 200 次；用覆盖 0–1 的确定性随机样本验证重连时间分散约 500 ms，恢复校时分散约 900 ms。这是逻辑与调度验证，不是公网吞吐压测。
- 实际本地 Chrome + 原生 EventSource：首次 1 GET/1 SSE；服务器断开后重新连接取得 revision 2，复核后本次观察耗时 827 ms（抖动范围内的单次结果），未额外 GET；Chrome 网络离线停止连接，在线恢复时隐藏文档分支取得 revision 3。
- dispose 后 SSE 活动连接为 0，已登记 online/offline/visibility 监听均为 0，再触发事件并等待 2.2 秒没有新请求。零页面脚本错误。
- 浏览器网络检查的隐藏分支使用可注入的文档可见性目标；没有声称完成操作系统后台标签调度、真实手机待机或三维 GPU 长测。没有写入正式场次、创建观众或调用模型。

原始网络报告：`artifacts/performance-200/live-client-browser/report.json`。

## 校时边界复核

首次校时允许纠正设备本地时间。此后的普通 RTT 估计变化使用 0.9–1.1 倍速渐进修正：时间不会倒退，不会停住等待旧估值被追上；误差消除后恢复正常速度。测试复现 200 ms 非对称 RTT 后改为 20 ms RTT 的 50 ms 回跳场景，确认修正改为 500 ms 内逐步收敛。

如果墙钟与单调时钟经过量相差超过 2 秒，视为可能发生系统休眠或本机改时，仅触发错峰服务端重校准，不信任本机墙钟值。可信服务端时间确认休眠跨度后可直接向前追到当前阶段；向后的修正仍渐进。跨越停钟边界的旧 HTTP 响应被忽略并合并补发一次新校准，避免旧响应取消醒来后的校时。另验证本机改时不能直接改变活动时间。
