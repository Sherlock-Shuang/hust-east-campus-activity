# 主持人编辑冲突与观众身份恢复

## 旧表单覆盖其他主持人的修改

复现：主持人甲打开入口或光柱的编辑表单；主持人乙修改同一个项目的位置；甲只修改名称并保存。原实现会把甲表单中的旧位置一起写回，覆盖乙的修改。

原因：保存前虽然读取了最新状态和版本号，随后却用整个旧表单替换项目。提交携带的是最新版本号，因此服务器的版本检查无法识别表单已经过期。

修改：打开编辑表单时记录该项目的原始内容；保存前，将它与刚读取的最新项目比较。内容发生变化时提示冲突，保留当前草稿；重新点击“编辑”即可载入最新内容。其他项目或活动状态的变化不影响当前项目的保存。服务器原有版本检查继续处理读取与提交之间的并发更新。

验证：入口和光柱的旧表单均不会覆盖最新修改；重新编辑后可以保存；其他状态更新可以保留；已删除项目不会被旧表单重新创建；清空表单后仍可以添加新项目。

## 首次身份查询失败后无法恢复

复现：已有昵称的观众在断网时打开页面，首次身份查询失败；恢复网络、切回页面或等待定时同步，原实现仍无法恢复身份和同步待发送记录。

原因：首次查询失败后，本地身份为空；后续心跳和记录同步都要求身份存在，没有入口再次查询身份。

修改：区分“身份查询失败”和“查询成功但尚未加入”。只有前者会在网络恢复、页面重新可见或每 15 秒的定时任务中重试。恢复身份和 CSRF token 后，继续心跳和待发送记录同步。恢复查询与手动加入共享进行中的请求，避免较晚返回的查询覆盖刚加入的身份。

验证：三种恢复触发方式均能恢复原身份并补发记录；手动加入与恢复同时发生时不重复查询；正常匿名用户不会反复查询；页面客户端销毁后，迟到的身份响应不再更新界面。
