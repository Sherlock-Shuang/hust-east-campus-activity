# C118 运行预算与生命周期优化

本轮基于 `f296205`，保留影院镜头、报告厅入口、海啸时间轴、游泳和原有人群动作。这里的测量是同机 Node CPU / 几何 / 实例上传范围，不是手机GPU帧率或现场设备保证。

## 实现

- `c118-performance.js` 复用校园自动画质和像素预算，读取同一画质偏好；手机从流畅开始，持续慢帧降级、健康运行后渐进恢复。报告厅独立测量自身负载，不照搬室外距离参数。
- 水面及门口浪头采用三档网格：流畅4,096 / 均衡9,600 / 清晰26,240三角形；飞沫128 / 320 / 640点。切档只替换当前两种网格并释放旧网格，不保留三套驻留。门口位置、CPU水位采样、游泳、时间进度和持续水流没有改动。
- NPC姿态更新15 / 20 / 25Hz；同一时刻与原算法的姿态一致。干燥时只上传14名走动NPC实际占用的矩阵前缀，固定就座者保持静态；每次销毁同时释放InstancedMesh自有实例资源。
- 接入帧间隔分布、CPU平均、绘制调用、三角形与几何/纹理对象计数；通过 `#hall-canvas` 的 `data-frame-metrics` 等字段验收。统计不把后台、全局暂停和恢复第一帧计为卡顿；这些CPU时间不等于GPU时间，对象计数不等于显存字节。
- 复用校园操作偏好：视角灵敏度、反转Y、摇杆大小与减少晃动；触控按屏幕比例归一化，不在报告厅另加常驻面板。失焦时不读取手柄，旋转/缩放窗口清理触控和按键。
- 图形上下文丢失时暂停输入、视频和音效，并保留返回校园操作。恢复后继续现有位置和活动时间；不生成新体验事件。Three.js仍负责内部图形资源恢复。
- UI水深/时间读数以10Hz更新，座位镜头过渡复用临时向量，避免每帧分配和不必要DOM写入。
- 室内座椅、灯具等InstancedMesh逐个释放自有实例缓冲，几何/材质/纹理继续按共享资源集合各释放一次，并从场景解除引用；重复销毁无副作用。
- 区分浏览器BFCache暂停与真正卸载。前进/后退恢复使用原房间、位置和活动身份，暂停时关闭输入与媒体；恢复重新读取操作/画质偏好且排除首帧间隔。真实卸载仍完整释放。桥接层若在订阅时同步告知已退出，及时注销订阅，不再建立新房间。

## 可重复测量

```sh
node scripts/benchmark-c118-runtime.mjs
node --test tests/c118-performance.test.mjs tests/c118-audience-motion.test.mjs tests/c118-flood-effect.test.mjs tests/c118-seating.test.mjs tests/c118-swimming.test.mjs tests/c118-cinema.test.mjs
```

条件：每批600帧、60Hz输入时间序列，217名虚拟NPC、固定事件时间，预热后3次测量。旧版本同一600帧水灾姿态CPU中位约555ms，新流畅约334ms、均衡约443ms、清晰约562ms。流畅约减少40%，清晰基本维持原有工作量；降低的是视觉更新频率，不是水位、玩家运动或活动同步精度。

动态NPC每次矩阵上传范围：旧实现保留容量263,872字节全量标脏；新实现干燥时15,232字节，水灾全员活动时236,096字节。初次GPU分配仍按容量进行，不将后续上传区间误称为减少全部驻留内存。
