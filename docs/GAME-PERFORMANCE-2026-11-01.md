# 校园、书境图书馆与晚言性能优化（2026-11-01）

本轮沿用现有地图、角色、交通数量、碰撞、输入、剧情和战斗。只修改校园运行代码以及匿名化的作品活动副本；没有写入生日礼物原工程，也没有重新打包其桌面版本。图书馆 GLB、晚言 Unity 四个运行文件保持原字节。

## 实施范围

- 校园交通人物、电动车按实例槽位更新，只发送变化矩阵；稳定颜色不随动作反复上传。复用选择数组减少临时分配，并合并同一绘制前的多次上传范围。详见 [交通等价性与微基准](TRAFFIC-RENDER-PERFORMANCE-2026-11-01.md)。
- 根据CPU采样进一步缓存同一角色、同一次扫掠路径的重复姿态；固定20Hz、邻居顺序和全部精确碰撞检查保留。3400次输入的公开状态与完成记录逐步完全一致。
- 作品覆盖校园时，不因公告、主持人暂停等状态变化重新绘制被遮住的校园；活动 DOM、实时消息、身份与记录继续工作，退出作品恢复校园绘制。
- 图书馆只冻结经核对没有动画/蒙皮/形变的建筑变换；动态门、角色、烟花保持独立。无变化时减少绘制和相机碰撞重复查询；第一人称及手机全屏剧情下不更新隐藏人物。书脊射线先筛选保守包围盒，再使用原精确三角形相交判定。
- 晚言使用有像素总量上限的分辨率预算和迟滞调节，降低高 DPI 超采样负担。宿主/图书馆暂停和页面隐藏真正暂停 Unity 主循环；恢复等两次真实引擎帧，退出清理监听器与调度。详见 [晚言验证及边界](WANYAN-PERFORMANCE-2026-11-01.md)。

## 校园移动前后对照（第一轮实例更新优化）

基线 `169d89c`，优化代码来自本分支；同机 Chrome、同路线、同「流畅」画质，真实点击开始体验，按住移动键与升空键。每个模式测量20秒。手机行还真实执行了地图拾取飞行器、触屏升空及浮动摇杆移动。测试串行进行，无其他代理同时执行浏览器压力测试。

| 条件 | 模式 | 原平均绘制帧率 | 新平均绘制帧率 | 原 / 新 >100ms 长帧 |
| --- | --- | ---: | ---: | ---: |
| 桌面1280×720，CPU4倍限速 | 步行 | 29.98 | 29.88 | 0 / 0 |
| 同上 | 飞行滑板 | 28.85 | 28.81 | 0 / 0 |
| 手机视口844×390，DPR2，CPU6倍限速 | 步行 | 10.40 | 15.88 | 57 / 0 |
| 同上 | 飞行滑板 | 11.21 | 17.60 | 49 / 3 |

桌面结果基本持平并接近该档30帧上限；手机模拟压力条件下P95间隔由约133ms降低到约83ms，仍没有达到30帧。每项仅一个20秒样本，不是统计显著性或所有手机性能保证。CPU限速、触摸视口不模拟低端GPU、内存压力、温度和现场网络；这些帧率来自实际渲染提交节奏，不是显示器逐帧呈现测量。

原始报告和截图：`artifacts/performance-20261101/campus/{baseline,optimized}-{desktop,mobile}/`。CPU交通微基准是另一种测量，不能与此帧率互相代替。

## 热点优化后的补测

在第一轮后增加局部交通扫掠缓存，同参数重新测试最终版：

| 手机CPU6压力条件 | 基线 | 仅实例更新优化 | 最终版 | 最终P95 / >100ms长帧 |
| --- | ---: | ---: | ---: | --- |
| 步行 | 10.40 | 15.88 | 28.00 | 50ms / 0 |
| 飞行滑板 | 11.21 | 17.60 | 18.96 | 66.7ms / 2 |

数据单位为实际绘制提交/秒；最终测试仍通过触控拾取、上升、浮动摇杆及真实移动距离检查。三阶段数据分开保留，最终版未再重复桌面上限样本。顺序单轮压力测试会受JIT、机器状态及低帧时间步上限影响，不将这一增幅当作所有设备固定倍率。飞行仍未达30帧；未修改游戏时间步以人为提高测量值。

交通自身500步交替CPU微基准中位2.444→2.043ms、P95 3.140→2.631ms；该值只衡量模拟，不用来替代完整浏览器表现。原始报告见`traffic-sweeps.json`、`campus/optimized2-mobile/`。

## 图书馆和晚言实测

图书馆 CPU4倍限速、相同模型/材质/分辨率：暂停背景2.5秒绘制从151次减至2次；第一人称行走本来接近60Hz，优化后基本持平；桌面第三人称初次对照由24.09到27.21次实际绘制/秒。第一人称隐藏角色的动画更新从148次降至0；手机全屏剧情也不再更新隐藏人物。最终版J921书架查询只在首次/镜头变化时精确求值，静止注视不再反复扫描；转身清空、转回重新高亮均通过。

图书馆桌面/手机布局的第一人称及书架近景四组截图，与基线逐像素一致。详细环境、初版A/B与最终补验区别见 [图书馆报告](../integration/library/LIBRARY-RENDER-PERFORMANCE-2026-11-01.md)。

晚言在1280×800、DPR2条件下实测canvas为1821×1138；原公式同条件约2428×1517，少约43.7%的像素工作量，不等于帧率提升。真实Unity已验证启动前暂停、暂停期间停止原生帧、嵌套暂停、恢复零额外位移、原暂停菜单保持、键盘恢复及暂停时退出。原PC包和可选Mobile包没有重建或偷偷换包，手机真机长时间战斗仍需实机测量。
