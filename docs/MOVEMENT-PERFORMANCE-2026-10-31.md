# 行走与飞行运行时优化 · 2026-10-31

本轮减少移动期间重复的场景筛选、实例上传和地面查询。地图密度、树木形态、材质、LOD 距离、控制方式、碰撞规则和 120 Hz 物理步进保持原有设置。

对照与回退基线：`7c503d104dcbe65f0c32c662638f6f9d62b95d5b`（`7c503d1`）。

## 实现

- 静态 XZ 索引缓存上一次查询的网格矩形及有序候选；跨格或范围变化时重算，精确距离和视锥测试继续执行。
- 实例矩阵与颜色只上传首个至末个变化槽位；多次更新发生在一次绘制之前时合并未上传范围，包括暂时隐藏的槽位。拾取 ID 数组复用，槽位记录按实际驻留容量分配。
- 植被与建筑的缓存视角跳过相同实例选择的重复扫描，同时继续检查驻留缩容和释放；新分配的缓冲区仍完整恢复当前选择。植被相机戳复用固定存储。
- 路线最近点查询使用包围树，保留原投影公式及等距时的源顺序。单调路线高度和路段查询使用二分查找，非单调输入保留线性路径。
- 悬浮板复用固定旋翼位置，移除结果未使用的重复接触查询；高于既有水面低空限制的水平飞行跳过无法改变判定的水域查询。桥面、身体净空与着陆检测继续执行。

- 飞行滑板的固定机身按相同材质、索引形式、阴影和渲染属性合批；旋翼、人物、透明运动盘和活动配件独立保留。可绘制网格从 317 降至 98（少 219 次主场景绘制提交），三角形仍为 137,128，活动可见几何缓冲仍为 5,722,176 字节。保留可按原名称检查的隐藏源零件，增加约 2.59 MB CPU 几何存储；这些源零件不再绘制。

- 场景相关 **28 项测试通过**，覆盖变化范围、连续更新、隐藏后重入、驻留缩容/释放/恢复，以及正负网格边界、查询范围变化和候选数组被调用方修改。
- 场景 A/B 对比 **579 个视角状态、1,544,866 个选中实例槽位、38 个几何/材质批次**；源 ID、矩阵、颜色、顶点属性、索引及被检查的材质参数完全相同。
- 运动相关 **169 项测试通过**。额外对比 **13 个场景、7,800 次完整运动状态**，覆盖步行、电动车、悬浮板、跑车、直升机、蜘蛛侠和船，含不同帧间隔与停顿；新旧完整状态逐次严格相等。

- 飞行器合批另有 **20 项回归通过**：顶点/法线/UV/索引、多个世界姿态、透明与活动部件分离、停车副本、重复进入和销毁。几何烘焙只允许 Float32 变换的微小舍入误差（世界顶点小于 `1e-6`），不将其描述为逐像素截图相同。详见 `artifacts/movement-performance-20261031/hoverboard-body-batch.json`。

## 测量边界

运行环境为 macOS arm64、Node v25.9.0。场景基准使用确定性的 7,800 棵树、1,200 株灌木和 20,000 点空间索引夹具。运动基准包含源地图的 299 栋建筑、41 段路线及合成栏杆、架空体、台阶、水岸和交通；不代表完整照片建筑碰撞世界的穷举验证。数个百分点的差异应视为小幅结果，不能推算实际设备 FPS。

这些结果衡量 CPU 和实例上传工作量，不测 GPU 执行、浏览器合成、显示刷新或手机温控；各项百分比也不能相加成整体收益。地图视觉与运动状态等价不替代真实低端设备的行走、起降与飞行检查。

## 最终浏览器 A/B

Mac17,2，10 逻辑核、24 GiB，Chrome 156.0.8078.76，Node24.22.1。生产模式临时构建，隔离服务与数据，仅本地构建注入计时/选取起点探针；没有把调试全局发布到正式网站。CPU 限速 6 倍，固定流畅档/30fps目标/0.85像素比，细节和阴影设置新旧一致。桌面1280×720、DPR1；手机横屏844×390、DPR2、触屏布局。

从原路线进度347.76m处出发；步行持续W，飞行板先用Q升空，再W+Shift加速。每段实际测量约20秒：步行约64m、飞行约722–724m。输入、原物理与碰撞持续运行；测试确认实际位移，阻塞路线不纳入结果。两版本按优化桌面→基线桌面→基线手机→优化手机顺序单独运行，没有并行Agent压测。

| 场景 | 平均绘制率：基线 → 优化 | P95帧间隔：基线 → 优化 | >100ms间隔：基线 → 优化 |
| --- | ---: | ---: | ---: |
| 桌面步行 | 27.9 → 28.8 fps | 50.0 → 50.0 ms | 0 → 0 |
| 桌面高速飞行 | 15.7 → 24.3 fps | 83.4 → 50.1 ms | 0 → 0 |
| 手机布局步行 | 28.1 → 27.9 fps | 50.0 → 50.0 ms | 0 → 0 |

主要收益集中于飞行。步行约28fps，基本持平；手机布局仍有一次超过100ms的间隔，不能声称已消除全部卡顿。每个条件只有一段20秒样本，系统和其他用户应用负载未控制，不将数个百分点差异当成可靠增益。此前探索中的21.7→27.9fps步行结果、13.7→22.2fps未合批飞行结果不作为最终结论。

手机项使用桌面Chrome的触屏/视口与CPU限速，移动输入仍通过真实键盘事件统一控制轨迹；不冒充真手机触控延迟、旧GPU或热降频测试。手机原触控回归由既有输入测试覆盖。
