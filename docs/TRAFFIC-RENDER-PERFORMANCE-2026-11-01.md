# 交通实例更新优化（2026-11-01）

本轮校园范围只修改通勤人物、电动车与停车实例的 CPU 选取和缓冲更新。地图、停车位置、车辆与人物模型、NPC 数量、近远景阈值、碰撞、步行/飞行/蛛丝控制没有改变。

## 改动

- 原先一个人物或车辆的姿态变化，会使包含它的每个部件批次整体重新计算矩阵和颜色。现在逐实例槽位比较身份及姿态版本，只写入变化槽位。
- 衣服、皮肤和车漆色与移动分开失效。位置/动作变化仍及时更新；颜色不变时不重新发送颜色缓冲。
- 每部件复用选择、版本、颜色与 ID 数组，交通分类复用六个近/远景数组，去掉每次更新的大量 `filter/map/slice` 临时数组。
- GPU 更新范围保留上次尚未绘制的数据。同一渲染帧内交通步进、取车/还车或相机移动多次调用更新，范围会合并；实例数暂时缩小也不会丢失尾部待上传内容。
- 借用动态车辆后停回地图导致停车容量增长时，重建该实例缓存并完整上传新缓冲；离开的角色不保留在槽位缓存中。

## CPU 微基准与等价核对

运行：

```sh
node --test tests/dynamic-instance-selection.test.mjs tests/commute-render-cache.test.mjs
node scripts/benchmark-traffic-render-cache.mjs --baseline-ref 169d89c
```

Node 24.22.1；基线 `169d89c`；350 个主路 NPC、232 辆静态停车、179 个实例部件批次。压力样本全选现有主路交通及停车，不进行可见范围削减。每种情况预热 60 次，记录 300 次更新；交替执行基线与优化版减少固定顺序影响。2026-11-01 单次结果：

| 更新情况 | 原中位耗时 | 新中位耗时 | 原 P95 | 新 P95 |
| --- | ---: | ---: | ---: | ---: |
| 全部不变 | 0.863 ms | 0.632 ms | 1.034 ms | 0.786 ms |
| 只有一个 NPC 变化 | 1.470 ms | 0.626 ms | 1.770 ms | 0.801 ms |
| 所有 NPC 移动 | 3.146 ms | 3.014 ms | 5.235 ms | 4.313 ms |

单个 NPC 改变的这一全选样本：矩阵写入 13,203 次降为 49 次；排队矩阵上传范围 844,992 字节降为 3,136 字节；颜色写入 6,755 次、排队 81,060 字节降为 0。

脚本还在实际路线的 48 个相机视角切换 0.45/1/1.25 细节预算，包含模拟步进及洪水开启/动画/清除，再核对取车还车：共 49 组有效实例矩阵、颜色、数量和身份哈希与基线完全一致。

这些数字是纯 Node CPU 微基准和待上传范围，不是 WebGL 实测 GPU 时间、整游戏帧率或真实手机测试。所有 NPC 同时运动时仍需计算每个动态姿态；本轮收益主要是停等/静止车辆、局部变动、颜色稳定和减少临时分配。全校园移动、飞行浏览器对照由统一验收脚本串行执行。

## 第一轮真实浏览器对照

Mac17,2 / Apple M5 / 24 GB、Chrome 156.0.8078.76、Node 24.22.1。本机临时生产构建与隔离活动服务，每轮新浏览器环境，真实点击入口封面，固定同一路线并用真实移动键步行 20 秒、起飞后加速飞行 20 秒。四轮串行；CPU 采样另开第五轮，不混入下表。流畅档均为 30 FPS 上限、0.85 渲染像素比、0.45 细节距离、关闭阴影与反射。

| 条件 | 模式 | 基线 FPS | 实例优化 FPS | P95 帧时间变化 | >100ms 长帧变化 |
| --- | --- | ---: | ---: | ---: | ---: |
| 桌面 1280×720 / DPR1 / CPU4 | 步行 | 29.98 | 29.88 | 49.9 → 49.9 ms | 0 → 0 |
| 桌面 1280×720 / DPR1 / CPU4 | 飞行滑板 | 28.85 | 28.81 | 50.0 → 50.0 ms | 0 → 0 |
| 触摸视口 844×390 / DPR2 / CPU6 | 步行 | 10.40 | 15.88 | 133.3 → 83.3 ms | 57 → 0 |
| 触摸视口 844×390 / DPR2 / CPU6 | 飞行滑板 | 11.21 | 17.60 | 133.3 → 83.4 ms | 49 → 3 |

桌面基本持平。触摸视口严重 CPU 压力下明显改善，但仍没有达到 30 FPS。仅单轮同条件对照，不能承诺所有电脑/手机有相同增幅，也不是物理手机、移动 GPU 或热降频测试。步行实际移动 61.8–64.5 米，飞行 687–723 米；基线低帧率下存在时间步上限造成的移动距离差异。两次手机测试均通过实际放置飞行器拾取、触摸上升与浮动摇杆移动，无页面 JS 异常。

原始报告、逐秒样本、机位截图：`artifacts/performance-20261101/campus/{baseline,optimized}-{desktop,mobile}/`；汇总 `comparison.json`。复跑脚本新增可选 `--cpu-profile`，保存 DevTools CPU profile 与源码映射，采样会引入额外开销，不应用其 FPS 与未采样结果比较。

独立 10 秒步行 CPU 采样指向交通模拟而非玩家碰撞：`commute-simulation.js` 自身采样耗时约 2846 ms，`integrate()` 自身约 1014 ms / 含子调用约 2845 ms，`step()` 含子调用约 3165 ms。`player-motion.js` 全文件自身约 257 ms。来源映射及核对的源码行保存在 `profile-mobile/cpu-walk-mapped.json`；原 `.cpuprofile` 与 `cpu-assets/*.js.map` 一并保留。

## 根据 CPU 采样补做：重复扫掠取样缓存

交通处理一个角色时，每个邻居都会测试同一段运动的起点、四分点、终点及二分中点。现在只在**同一角色、同一次固定扫掠路径**内缓存完整 `poseForAgent(t)` 返回结果和对应道路检查结果。直行与侧移各有独立缓存，角色处理结束即释放；不跨帧，不缓存会被后续偏移修改的 `centerPose` 对象，也不缓存其他角色的可变位置。

模拟仍按 20 Hz 固定步长，所有相邻角色、精确碰撞、九次二分、玩家障碍、让行、排序与先行者处理顺序完全保留。未改人口、道路、操作或速度参数。

```sh
node scripts/benchmark-traffic-sweeps.mjs --baseline-ref 169d89c --output artifacts/performance-20261101/traffic-sweeps.json
node --test tests/commute-sweep-cache.test.mjs
```

四种场景共 3400 次输入与独立的 `169d89c` 源实现逐次比较整个公开状态及保留的离场/完成记录；全部完全一致。覆盖真实校园 350 人高峰双向、时间与密度/骑车比例重置、移动地面玩家阻挡与高空飞行、窄桥双向让行、红/黄/绿/关灯、变道、车身扫掠、道路边界、借还车、24 次下车步行及抵达终点。原实现完整状态序列的哈希固化到测试夹具，4 项回归通过。

独立 CPU 微基准交替执行优化前后，每版 100 次预热 + 500 次实际 20 Hz 更新：中位 **2.444 → 2.043 ms**，P95 **3.140 → 2.631 ms**，约 16–17% 降低。该时间仅代表交通模拟 `step()`，不是整游戏帧时间。数据见 `artifacts/performance-20261101/traffic-sweeps.json`；改变负载或设备会改变绝对耗时。

补做同参数手机 CPU6 浏览器复测，另存 `optimized2-mobile/`，保留前面两版原始结果：

| 模式 | 基线 FPS | 仅实例优化 FPS | 加入扫掠缓存 FPS | 最终 P95 / >100ms 长帧 |
| --- | ---: | ---: | ---: | ---: |
| 步行 20 秒 | 10.40 | 15.88 | 28.00 | 50.0 ms / 0 |
| 飞行滑板 20 秒 | 11.21 | 17.60 | 18.96 | 66.7 ms / 2 |

最终移动 64.16 米 / 723.00 米，画质预算与路线一致，手机实际拾取飞行器、触摸上升 9.13 米、浮动摇杆移动 23.56 米均通过，没有页面 JS 异常。该单轮步行结果增幅较大，不能将整场景的非线性帧率变化全部当作某一函数的固定收益；确定的函数收益以交替 CPU 基准为准。飞行仍有长帧且未到 30 FPS，本轮不宣称真实低配手机已经稳定流畅。
