# 校园鼠标锁定兼容

校园保留中键与 L 锁定，并在操作提示中提供可以直接点击的“锁定鼠标”按钮。按钮使用当前用户的点击同步请求锁定，适合无法通过中键或键盘触发锁定的环境。按钮覆盖提示容器的 `pointer-events:none`；纯触屏界面隐藏它，带鼠标的混合设备仍可使用。

中键同时支持 PointerEvent 与 MouseEvent，同一次按下只切换一次。L 优先识别物理键，在缺少键码的环境使用字母回退；输入法组合、文字输入、暂停和退出后的输入不会触发锁定。

锁定成功以浏览器实际持有的元素为准，不会只隐藏光标或显示假的成功状态。共享请求层兼容标准及旧前缀接口，等待结果有超时，失败后可用新的用户操作重试。取消、失焦与销毁后的迟到成功仍会释放；旧请求的失败不会取消新的 Promise 请求。

失败原因保留在操作提示中，直至重试或成功。微信内置浏览器中的失败会提示直接点击重试；如果内核仍拒绝，用户可以在系统浏览器打开同一页面。普通鼠标环视始终保留，不自动重复申请权限。

浏览器仍有最终决定权：焦点、用户交互和 iframe 的 `allow-pointer-lock` 是原生 Pointer Lock 的要求，网页不能绕过拒绝或伪造原生锁定。参见 [Pointer Lock 规范](https://www.w3.org/TR/pointerlock/) 和 [requestPointerLock 文档](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestPointerLock)。

验证覆盖共享请求状态机、校园鼠标/键盘/按钮输入、取消和迟到事件、拒绝及无响应后的重试。浏览器验收区分真实原生请求与注入的失败场景；模拟微信 UA 不代表在真实微信客户端验收。
