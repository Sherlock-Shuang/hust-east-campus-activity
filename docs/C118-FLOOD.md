# C118 海啸演出

更新：2026-10-30。本版本包含 C118 大屏视频与海啸演出，支持本地 Node 活动服务及现有 Vercel + Turso 云端活动服务。

## 主持人使用

1. 云端打开 [主持人控制台](https://www.the-most-interesting.online/admin) 并登录。本地可运行 `npm run dev -- --host 127.0.0.1 --port 5178`，访问 `http://127.0.0.1:5178/admin`。仅运行 Vite 静态预览不能提供统一控制所需的活动 API。
2. 让观众从校园进入光电大楼 C118。单独预览报告厅也可使用 `http://127.0.0.1:5178/c118.html?view=front`，它会连接同一活动服务。
3. 在后台「C118 海啸演出」点击「触发海啸」。服务端统一安排在接受操作约 3 秒后开始；各观众使用同一场次和时间轴，无需分别点击播放。
4. 演出开始后，水浪由报告厅四个门口冲入，水位快速上涨，约在演出时间 18 秒达到高水位，随后保持淹没状态。门口浪头从演出时间约 1.5 秒开始出现，中部门口略错开，形成前后冲击。未暂停时，从点击触发到高水位约 21 秒。
5. 「暂停全体玩家」冻结倒计时或正在进行的海啸；「恢复全体玩家」从暂停点继续。暂停时停止音效与操作，不重新播放开场。
6. 点击「恢复报告厅」清除当前海啸，恢复干燥报告厅。清除后才可再次触发；重复点击或其他主持人的旧页面不会覆盖新场次。此操作不解除全场暂停。

只有身处 C118 的玩家看到水浪、水下雾和镜头效果；校园室外及其他作品不接收 C118 海啸内容。晚进入报告厅、刷新或切回页面的观众按当前服务端时间追平，不从头播放。演出不会自动结束，主持人结束展示时应点击「恢复报告厅」。

## 观众体验与声音

- 海啸正式开始后，大屏视频及其配乐自动暂停，视频控件暂时隐藏。恢复报告厅后按原有播放规则继续：需要页面可见、面向大屏，且没有被观众手动暂停。
- 观众在报告厅内点击画面或按键后解锁浏览器音频。未交互、浏览器禁止音频或设备不支持 Web Audio 时仍可正常观看水浪，不自动绕过浏览器限制。
- 音效由程序生成，包含低沉水声、冲击水流与水下低通轰鸣；没有新增外部音源或音频下载。切到后台、全场暂停、离开报告厅及销毁页面时立即静音。
- 水面越过眼睛后出现青色水下雾、边缘水滴和轻微晕染，仍保留场景辨识度。演出不使用全屏闪白。
- 遵循系统或浏览器的「减少动态效果」（`prefers-reduced-motion: reduce`）：关闭镜头冲击晃动与漂浮，降低水面波纹及覆盖层位移；仍显示海啸与水位变化。

## 同步数据流

```text
后台 admin-control.js
  → 带管理员会话、CSRF 与 expectedRevision 的 PUT /api/admin/state
  → 本地 server/index.mjs 串行写入 JSON
    云端 serverless/activity-api.mjs 以 Turso revision CAS 写入
  → 统一服务端排期、持久化与状态分发
  → /api/live/state 快照 + /api/live/events 实时推送
  → live-client.js 的校准服务端时钟
  → 校园内 C118：live-experience.js → 同源 activity-bridge.js
    直接打开 C118：c118-activity-sync.js 自己创建一个 live client
  → c118-viewer.js 按 elapsed 驱动水浪、音效、镜头与视频暂停
```

场次保存在全场状态的 `c118Flood` 字段中；没有演出时为 `null`。事件结构为：

```js
{
  id: '本场唯一标识',
  startAt: 服务器接受触发时间 + 3000, // 毫秒
  pausedAt: null,                    // 暂停时为服务端暂停时间
  pausedMs: 0                       // 累积暂停时长，毫秒
}
```

`src/c118-flood-state.js` 校验字段并统一计算：

```js
elapsed = ((pausedAt ?? serverNow) - startAt - pausedMs) / 1000;
```

服务端只在新场次 ID 出现时创建时间轴；同一场次的客户端时间不能改写服务端排期。全场暂停时记录 `pausedAt`，恢复时累加 `pausedMs`，因此倒计时也会冻结。旧管理端保存其他设置而省略 `c118Flood` 时保留现有演出，只有显式 `null` 才清除。写入通过版本号与服务端队列处理冲突，成功持久化后才广播。

嵌入校园的报告厅共用父页面实时连接，不再建立第二条连接；桥接仍核对来源、父窗口与 `attemptId`，并只向 `opto-c118` 传递事件。直接打开报告厅则使用独立活动客户端。水浪以服务器经过时间求值，不靠每帧累加，能够直接定位到中途或高水位状态。

## 验证步骤

建议同时打开一个后台、两个 C118 观众窗口和一个校园室外窗口。手工验收时保持正在比较的观众窗口可见，避免浏览器后台节流干扰判断。

1. 在观众窗口点击画面解锁声音，再从后台触发。确认后台约 3 秒统一排期；两个报告厅的浪头推进与水位对应同一进度，室外窗口没有水浪、音效或水下覆盖。
2. 分别查看前排与后排，确认四个实际门洞有冲入的浪头，约 18 秒到高水位，后部阶梯座位区域也被覆盖，水面未穿过天花板。
3. 演出期间另开一个 C118 或重新进入，确认追上当前进度；不要要求重新观看开场。
4. 在倒计时和涨水阶段分别操作全场暂停，等待数秒再恢复，确认从暂停点继续。暂停时音效停止，视频也不播放。
5. 演出中点击「恢复报告厅」，确认水面、雾、覆盖层和音效消失，视频按原播放条件恢复；再触发应是新的一场。也应验证全场暂停期间恢复报告厅的边界情况。
6. 切后台、返回校园、重新进入，检查没有残留声音、旧场次覆盖或重复实时连接。海啸持续时重新进入仍会追平；已恢复时重新进入保持干燥。
7. 开启系统「减少动态效果」后复验，确认镜头不晃动，水位仍按统一时间推进。
8. 用不同设备、实际现场网络与扬声器补测帧率、同步观感及音量。自动测试不能代替真实浏览器画面、设备性能和听感验收。

可在开发工具检查 `#hall-canvas` 的 `data-flood-event`、`data-flood-elapsed`、`data-water-height` 和 `data-video-state`，用于对照场次与时间。不同视点的水位采样会受到局部浪头影响，不能仅以 `water-height` 完全相等作为同步判据。

## 当前范围与验收限制

- 这是依报告厅布局设计的实时演出，没有求解真实流体方程，也不模拟家具漂浮、人物受力、溺水伤害或全校园洪水。玩家使用原有行走规则。
- 同步依赖同一活动服务的状态与校准时钟；网络延迟和设备帧率会造成短暂观感差异，恢复连接后追平，不保证逐帧锁步。尚未进行现场多设备网络和扬声器听感验收。
- 部署不清空活动数据库、观众记录或管理设置。旧持久化状态没有海啸字段时按关闭处理；已触发事件在重启后继续存在，结束展示需点击「恢复报告厅」。
- 云端时间轴由服务器计算并持久化至 Turso，不能只部署水面前端。现有管理员权限、CSRF 与版本冲突检查保持生效，未增加公开触发接口。
