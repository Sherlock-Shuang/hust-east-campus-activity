# 活动服务公共读取优化与隔离持续验收

本文实现、测试及压测命令适用于 `deployment/optimization-release-20261030` 工作区或线上 Git 部署仓库。主目录继续使用现有本地 Node 服务；没有新增缺失的 serverless handler，也没有在主目录启用这项 SSE 缓存。以下命令须先进入完整部署仓库执行。

## 公共状态读取

原SSE客户端每1.5秒独立查询一次活动状态。现在同一服务进程、同一数据库适配器的SSE读者共享一次在途读取，成功结果最多缓存500ms；多个流同时读取不重复发出相同SQL。

- 缓存只用于SSE的公共状态行，不包含身份、昵称、管理员会话、CSRF、模型额度、观众记录或认证结果。
- 管理员CAS写入、入口是否开放的原子校验、`GET /api/live/state`、统计和身份接口继续读实际数据库；没有拿缓存作为放行依据。
- 只有成功提交的管理员写入才将新revision发布到本实例缓存。较早的在途SELECT晚返回时，不能覆盖已提交的新revision，也不能将旧值交给等待中的SSE。
- 使用数据库适配器对象作为WeakMap作用域；不同数据库环境独立。缓存不跨Vercel实例传播，不替代Turso持久化。其他实例的写入在短TTL过后读取，SSE原1.5秒周期和240秒轮换保持不变。
- 无效认证、个人数据和统计查询均不缓存；人数刷新逻辑没有变化。受网络/函数实例数量影响，实际生产DB节省幅度必须测量，不能把同进程合并比率当作整个集群比率。

实现：`serverless/public-state-cache.mjs`、`serverless/activity-api.mjs`。

## 30分钟HTTP/SSE持续测试

```sh
node scripts/soak-activity-local.mjs --seconds 1800 --audiences 100 \
  --output artifacts/optimization-2026-10-30/activity-soak-100-30min.json
```

脚本不读取`.env`，不接受远程URL。它创建全新的临时SQLite文件、两个实际serverless handler和本地HTTP服务，通过真实HTTP测试100名合成身份、100条SSE，每15秒发送心跳，每分钟切阶段/暂停，每3分钟断开10条流后重连。240秒生命周期使用真实墙钟，不使用加速时钟。

初次加入分别记录不同点位到访、成功打开/失败、返回及重复事件，并让10名观众再开一个标签。结束检查独立总人数、在线人数、每点到访、每作品打开、当前体验为零，以及所有连接租约清理。数据、cookie与密码只在隔离环境内使用，日志不打印凭据。脚本结束销毁本次临时数据库。

该持续测试验证连接、事件和持久化逻辑，不验证现场Wi-Fi、Turso公网延迟、CDN流量、100台真实GPU、多人角色同步或作品实际画面。最终通过状态与实测数值以对应JSON的`passed`、持续时间和错误列表为准；脚本启动不等于通过。

初次长测在约19.2分钟因未分类的HTTP `fetch failed` 提前结束，记录为 `activity-soak-initial-19min.json/log`，不计作30分钟通过。之后脚本增加route/cause记录，并仅对GET、心跳和稳定eventId事件允许一次安全重试；恢复后的异常仍单列 `transientErrors`，不会隐藏。新身份创建和管理员提交不做盲重试。
