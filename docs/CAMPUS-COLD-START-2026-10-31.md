# 现场首次加载与后台地图细节

适用场景：200 人以上在同一现场／校园 Wi-Fi 上，活动开始时才首次打开游戏。无需参加者提前打开或预下载。

## 入场与地图细节

校园首先建立道路、楼体轮廓、完整碰撞、步行支撑面和入口。普通建筑远区立面、树林、草坪景石、东九前场及水生植物继续分阶段补全。食堂树干、灯杆和停车规划仍先完成；纯外观的地面树影网格改在入场后分片规划和生成，保持最终点位和几何一致。`survey.js` 使用 `deferDetails:true`，在首帧提交后的下一次动画帧调用 `campus.startDetails()`；不会在玩家建立过程中提前运行后台几何任务。

后台让出浏览器空闲时间（`requestIdleCallback`，最长等待 250 ms；不支持时延迟 32 ms），任务片预算 3 ms。预算只控制生成器任务之间的调度，不能抢占单个同步任务，不能宣称消除所有长帧。取消或销毁也会结束尚未开始的后台等待。

这不是全校园地图网络分块下载：核心地图数据仍一次取得，以保持全部碰撞、入口与手工点位一致。作品／视频沿用按入口或场景需要加载，不计入校园首帧下载量。

## 网络故障恢复

- 三份地图文件在小入口脚本执行时开始，与场景脚本并行，共用 Promise，已经成功的文件不会因另一份失败而重新下载。
- 主地图和补充地图每次最多等 45 秒（包含响应体），最多两次请求。仅网络失败、429、5xx 重试，间隔随机 1–4 秒，避免全场同步重试。
- 地图说明最多等 12 秒一次；失败时使用内置固定原点，避免手工建筑／入口坐标整体移动。
- 30 秒仍未就绪时显示重试提示，正常下载继续。提示与样式直接在 HTML 中，即使外部入口 JS／CSS 失败也可用。最终失败有明确原因与重试按钮。

## 已有体积观测和现场边界

单次正式站无缓存访问观测到首帧完成请求的正文共 787,190 字节（约 0.79 MB）；不是数百 MB 的整个作品目录。已验证 Brotli 压缩与 CDN 缓存。出生地附近的群二维码另有约 0.55 MB，初期预算可按约 1.34 MB／人估算。测量为桌面 Chrome 模拟手机视口，不是手机耗时／现场容量验收。

300 人的初期传输预算约 402 MB。假设全场对本站的有效总下行为 100 Mbps，纯传输理论下限约 32 秒；还不含无线竞争、重传、握手与手机构建时间。单人测速、AP 标称带宽、已有本地 HTTP／SSE 压测，都不能替代现场 200 多台设备冷启动验证。

活动前由工作人员在实际场地、实际校园 Wi-Fi、不使用代理，验证本站可达性和多终端首次进入；请网络管理员按人数确认 AP／无线射频容量、认证与地址分配能力和出口吞吐。参与者仍在活动开始时才首次打开。开场先进入校园，较大的作品保持按需进入。网络容量不足时，软件分阶段构建仍不能保证同时进入时长。
